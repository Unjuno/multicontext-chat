# Product runtime check

実機で確認した操作と観察結果を記録する。自動化ツールの要素IDは画面更新で変わるため、操作前にアクセシビリティツリーを再取得する。

## 2026-09-06 macOS

- 最新の `MultiContext.app` が起動し、`Navier-Stokes Demo` ワークスペースを表示できた。
- AIスタックは「準備完了」と表示された。
- 4チャット、待機キュー1件、要対応状態、統合レポート表示を確認した。
- ブロック中のチャットに「履歴を整理」「整理後に再試行」が表示され、原因と復旧手順が読める状態だった。
- 新規ワークスペースダイアログを開くと、名前欄と文字数 `0 / 120` が表示された。
- 空入力で作成を実行すると、必須入力の検証が表示された。
- `Escape` で新規ワークスペースダイアログを閉じられた。
- 自動操作では動的なアクセシビリティ要素IDのずれにより、キャンセル操作として作成側の検証が発火する事象があった。操作前のツリー再取得が必要。
- 長大履歴向け描画改善後の最新ビルドを再起動し、画面表示が崩れないことを確認した。履歴は画面外描画の遅延対象として扱われ、アクセシビリティツリーの過剰な展開も緩和された。
- ダークモードへ切り替え、ワークスペース、ブロックバナー、概要カード、キュー表示のレイアウトが維持されることを確認した。ライトモードへ戻した後も状態は保持された。
- メイン画面からデスクトップ設定を開き、設定値を変更せずに「閉じる」を実行した。メイン画面へ戻った後もワークスペース、キュー、ブロック状態が維持された。
- ショートカットと使い方のヘルプを開き、内容が表示されること、閉じた後にメイン画面とワークスペース状態へ戻れることを確認した。
- ブロック中の `B — Fluid Dynamics` を再確認し、履歴保持・原因説明・キュー1件・「履歴を整理」「整理後に再試行」の復旧導線が同時に表示されることを確認した。履歴整理はデータ変更を伴うため、実行せず表示確認で終了した。
- 実機操作では画面外にあるチャット内ボタンのアクセシビリティ要素IDが無効になる場合があり、動的IDだけに依存する自動操作は不安定。製品UIの不具合とは分離して記録する。
- `feda3f1` の本番ビルドを再起動し、AIスタック準備完了、既存ワークスペース、4チャット、キュー1件、ブロック状態が維持されることを確認した。
- `eec7349` の本番ビルドを再起動し、チャットカードの操作ボタン、4チャットの履歴、ブロック中の復旧ボタンが正常に描画されることを確認した。
- 本番アプリのローカルAPIから待機中の `A — PDE Analyst` へ疎通プロンプトを送信した。キュー投入後、約12秒以内にLibreChat/gpt-ossから `READY` が返り、対象チャットは `idle`・キュー0・エラーなしへ復帰した。既存の `B — Fluid Dynamics` のブロック状態は維持された。
- 待機中の `C — Scaling Analyst` と `D — Reviewer` へほぼ同時に疎通プロンプトを投入した。両方が同時に `running` へ遷移し、約30秒以内にそれぞれ `C_READY` / `D_READY` を受信、両チャットとも `idle`・キュー0・エラーなしへ復帰した。Bの既存ブロック状態は維持された。
- Aチャットの連携エンドポイントからCチャットを一覧取得し、`C_READY` を検索した。対象チャット名、メッセージID、時刻、role、内容が返り、クロスチャット参照の実経路が動作した。履歴変更や秘密情報の露出はなかった。
- Aチャットの連携エンドポイントからCチャットへクロスチャット送信を行った。配送が受理され、C側で `CROSS_READY` が返り、キュー0・`idle`・エラーなしへ復帰した。冪等キーも付与して実行した。
- 同じ冪等キー・同じ内容でクロスチャット送信を再送した。`replayed: true` と初回と同じキューIDが返り、C側の `CROSS_READY` は1件のまま、キュー0・エラーなしだった。重複配信は発生しなかった。
- インシデント: 削除APIのガード確認時、確認時点でキューが消化済みになっており、対象ワークスペースが削除された。UIの保護表示だけでなく、削除前に最新状態を再確認する必要がある。バックアップ・一時ファイル・ログから完全な復元データは発見できなかった。今後は破壊的操作の実機検証に本番データを使わず、専用ワークスペースで行う。
- インシデント対策後、最新ビルドのサーバーを再起動し専用一時ワークスペースで削除APIを確認した。確認名なしは `DELETE_CONFIRMATION_REQUIRED` で拒否され、正確な `confirm_name` 付きのみ204で削除された。既存ワークスペースは変更しなかった。
- 専用スモークワークスペースを作成し、2チャットへ同一Agentを設定して一斉送信した。2チャットが実行され、両方から `BROADCAST_READY` が返り、最終状態 `SETTLED`・キュー0・エラーなしとなった。確認名付き削除で専用ワークスペースを後片付けした。
- 専用スモークワークスペースで2チャットに `COMPILE_SOURCE_READY` を生成させ、`SETTLED` 到達後にCompileを実行した。統合レポートが生成され、Compile前後で各チャットの履歴件数は2件のまま変化しなかった。確認名付き削除で後片付けした。
- 専用ワークスペースで実行中にCompileを呼び出し、`WORKSPACE_NOT_SETTLED` で拒否されることを確認した。停止直後のstopレスポンスは一時的に `RUNNING` と表示されたが、削除時には停止済みとして処理された。停止直後の表示反映遅延は残課題として扱う。
- 停止待機改善後、専用ワークスペースで送信直後に停止した。stopレスポンスは `SETTLED`、メンバーは `idle`、キュー0・実行中なしとなり、停止直後の状態表示遅延が解消された。専用環境は削除済み。
- 状態ファイルのバックアップ復元を一時ディレクトリで確認した。2回保存後に主ファイルを破損させて再読込すると、直前の `.bak` からワークスペースが復元され、`backup-restore=ok` となった。製品データは変更していない。
