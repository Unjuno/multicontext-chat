# Product runtime check

実機で確認した操作と観察結果を記録する。自動化ツールの要素IDは画面更新で変わるため、操作前にアクセシビリティツリーを再取得する。

## 2026-09-06 macOS

- 最新の `MultiContext.app` が起動し、`Navier-Stokes Demo` ワークスペースを表示できた。
- AIスタックは「準備完了」と表示された。
- 4チャット、待機キュー1件、要対応状態、統合レポート表示を確認した。
- ブロック中のチャットに「履歴を整理」「整理後に再試行」が表示され、原因と復旧手順が読める状態だった。
- 新規ワークスペースダイアログを開くと、名前欄と文字数 `0 / 120` が表示された。
- 空入力で作成を実行すると、必須入力の検証が表示された。
- `Escape` で新規ワークスペースダイアログを閉じられた。
- 自動操作では動的なアクセシビリティ要素IDのずれにより、キャンセル操作として作成側の検証が発火する事象があった。操作前のツリー再取得が必要。
- 長大履歴向け描画改善後の最新ビルドを再起動し、画面表示が崩れないことを確認した。履歴は画面外描画の遅延対象として扱われ、アクセシビリティツリーの過剰な展開も緩和された。
- ダークモードへ切り替え、ワークスペース、ブロックバナー、概要カード、キュー表示のレイアウトが維持されることを確認した。ライトモードへ戻した後も状態は保持された。
- メイン画面からデスクトップ設定を開き、設定値を変更せずに「閉じる」を実行した。メイン画面へ戻った後もワークスペース、キュー、ブロック状態が維持された。
- ショートカットと使い方のヘルプを開き、内容が表示されること、閉じた後にメイン画面とワークスペース状態へ戻れることを確認した。
- ブロック中の `B — Fluid Dynamics` を再確認し、履歴保持・原因説明・キュー1件・「履歴を整理」「整理後に再試行」の復旧導線が同時に表示されることを確認した。履歴整理はデータ変更を伴うため、実行せず表示確認で終了した。
- 実機操作では画面外にあるチャット内ボタンのアクセシビリティ要素IDが無効になる場合があり、動的IDだけに依存する自動操作は不安定。製品UIの不具合とは分離して記録する。
